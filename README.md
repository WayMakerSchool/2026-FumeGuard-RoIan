# FumeGuard AI

인터넷 없이 ESP32와 BLE로 직접 연결하는 조리흄 실시간 모니터링 데모입니다.

## 실행

```bash
npm start
```

AI 정밀 분석은 로컬에서 실행한 [FreeLLMAPI](https://github.com/tashfeenahmed/freellmapi)(OpenAI 호환 라우터, 데스크톱 앱 기본 `http://127.0.0.1:31415/v1`)를 호출합니다. FreeLLMAPI를 먼저 실행하고 대시보드에서 제공사 키를 등록한 뒤, Keys 페이지의 통합 키(`freellmapi-…`)를 `.env` 파일(`.env.example` 참고)에 넣고 실행합니다. `npm start`가 `.env`를 자동으로 읽습니다. 키를 HTML이나 `app.js`에 넣지 마세요.

- `LLM_BASE_URL`: 다른 OpenAI 호환 서버를 쓸 때 지정합니다(기본 `http://127.0.0.1:31415/v1`. Docker/npm으로 실행한 FreeLLMAPI는 `http://127.0.0.1:3001/v1`).
- `LLM_MODEL`: 사용할 모델 ID. `.env.example`은 `gemini-3.6-flash`(약 7초, 정확)로 고정합니다. 더 빠른 응답은 `gemini-3.5-flash-lite`(약 1초). 지정하지 않으면 라우터가 고르는 `auto`이며, 지정한 모델이 실패하면 `auto`로 한 번 더 시도합니다.
- 무료 등급 라우터라 응답 속도와 모델이 요청마다 달라질 수 있습니다.

출력된 주소를 Chrome에서 엽니다. 화면의 `위험 상황 시연` 버튼만으로 센서 없이 전체 발표 흐름을 시연할 수 있습니다.

## 대시보드

- 첫 화면은 **시연 모드**입니다. 15분 분량의 가상 이력을 보여주며 1초마다 갱신합니다. 화면과 CSV에 시연 데이터임을 표시합니다.
- `위험 상황 시연`을 누르면 오염물질 농도와 위험도가 상승합니다. 다시 `환기 회복 시연`을 누르면 서서히 회복합니다.
- 공기질 그래프에서 PM2.5 / VOC / CO와 1분 / 5분 / 15분을 선택할 수 있습니다. 그래프 위에 포인터를 올리면 측정 시각과 수치를 확인할 수 있습니다.
- 위험도 게이지, 3종 미니 그래프, 위험도 기여 도넛, 분별 위험도 타임라인, 환기 개념 애니메이션을 제공합니다. 애니메이션은 실제 후드 제어 상태를 나타내지 않습니다.
- `센서 연결`을 하면 시연 모드를 끄고 실제 ESP32 데이터를 수신합니다. 유효한 데이터가 없거나 10초 동안 수신하지 못하면 현재 수치와 위험도는 측정 대기로 표시합니다.
- 연결이 예기치 않게 끊기면 1·2·4·8·8초 간격으로 최대 5번 자동 재연결합니다. 직접 `센서 연결 해제`를 누른 경우에는 재연결하지 않습니다.
- 실제 측정 기록은 브라우저에 최근 900건까지 저장됩니다. `기록 내보내기`는 현재 데이터 출처와 측정 시각을 포함한 CSV를 내려받습니다. `기록 초기화`는 현재 모드의 기록을 지웁니다.
- 세션 누적 노출은 현재 세션에서 위험도 30 이상인 측정 시간입니다. 페이지 새로고침이나 모드 전환 시 새로 계산합니다. 센서 수신 공백을 노출 시간으로 가산하지 않습니다.
- 종 모양 버튼으로 위험 단계 진입 시 알림음을 켜거나 끕니다. 안전 가이드는 클릭으로 열고 Escape로 닫을 수 있습니다.
- Pretendard 가변 폰트를 로컬에 포함했습니다. 기본 대시보드와 BLE 연결은 외부 네트워크가 필요 없으며, AI 정밀 분석에는 서버의 API 키와 인터넷 연결이 필요합니다. 폰트 라이선스는 `assets/fonts/OFL.txt`에 있습니다.

## 에어커튼 바람 제어

`에어커튼 바람` 카드에서 모드와 바람 단계(1~3단)를 고릅니다. 설정은 브라우저에 저장되고, 센서가 연결되면 에어커튼으로 전송됩니다.

| 모드 | 동작 |
|---|---|
| 끄기 | 바람을 끕니다. |
| 수동 | 고른 단계로 계속 가동합니다. 위험도가 바뀌어도 그대로입니다. |
| 자동 | 위험도에 따라 바꿉니다. 안전 꺼짐 · 주의 1단 · 위험 2단 · 매우 위험 3단. |
| 상시 가동 | 고른 단계 아래로 내려가지 않고, 위험도가 오르면 자동으로 더 세게 붑니다. |

- 끄기·자동 상태에서 단계 버튼을 누르면 그 단계의 수동 모드로 바뀝니다. 상시 가동에서는 기본 단계가 바뀝니다.
- 자동 단계는 올릴 때는 즉시 올리고, 내릴 때는 위험도가 10초 동안 낮게 유지된 뒤에 내립니다.
- 자동 단계는 앱이 계산해서 보냅니다. 앱 연결이 끊기면 에어커튼은 마지막으로 받은 단계를 유지합니다.
- 시연 모드에서는 화면에만 표시하고 기기로 보내지 않습니다.

Web Bluetooth는 보안 정책상 HTTPS 또는 localhost에서만 동작하며, Android Chrome/데스크톱 Chrome을 권장합니다. iOS 브라우저에서는 Web Bluetooth가 제한될 수 있습니다.

## ESP32 BLE 데이터 규격

- 기기 이름 접두어: `FumeGuard`
- Service UUID: `12345678-1234-1234-1234-123456789abc`
- Notify Characteristic UUID: `87654321-4321-4321-4321-cba987654321`
- UTF-8 JSON 예시: `{"pm":35,"voc":420,"co":2.1,"temp":25.2,"humidity":51}`
- 다섯 값이 모두 숫자여야 합니다. 문자열이거나 빠진 값이 있으면 앱이 그 알림을 버리고 안내를 띄웁니다.
- 선택: `"fan":2`처럼 현재 바람 단계(0~3)를 함께 보내면, 앱이 보낸 값과 다를 때 화면에 알려 줍니다.

### 바람 제어 (앱 → ESP32)

- Write Characteristic UUID: `87654321-4321-4321-4321-cba987654322` (같은 Service, Write with response)
- UTF-8 JSON: `{"fan":2,"mode":"manual"}`
- `fan`: 적용할 바람 단계. 0은 꺼짐, 1~3은 단계입니다. ESP32는 이 값만 적용하면 됩니다.
- `mode`: `off` / `manual` / `auto` / `always`. 참고용이며 단계 계산은 앱이 합니다.
- 이 특성이 없는 펌웨어에 연결해도 모니터링은 그대로 동작하고, 바람 제어 카드에 지원하지 않는다고 표시합니다.

## 개발

```bash
npm test
```

- `logic.js`: 위험도 계산, 바람 단계 결정 등 화면과 무관한 로직. `app.js`와 테스트가 함께 씁니다.
- `app.js`: 화면 갱신, 시연 데이터, BLE 연결.
- `server.mjs`: 정적 파일과 `/api/analyze`. 화면에 필요한 파일만 내주고 `.env`, 서버 코드 등은 404로 응답합니다.

현재 AI 위험도는 PM2.5, VOC, CO 농도와 PM2.5 상승 속도를 결합한 설명 가능한 엣지 분석 모델입니다. 실제 제품화 단계에서는 보정된 센서와 검증 데이터로 임계값 및 모델을 재학습해야 합니다.
